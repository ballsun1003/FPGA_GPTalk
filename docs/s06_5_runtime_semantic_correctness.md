# S06.5 Runtime Semantic Correctness

## Verdict

S06.5 is partially recovered, but S07 gate is **not ready**.

Tokenizer decode, chat-template logging, CPU-only semantic baseline, board-side full generated text decode, and serial/stdout interactive mode are fixed. The FPGA path no longer emits the original broken byte stream for the `Hello, how are you?` raw prompt after adding a runtime-only FPGA repair pass for saturated row outputs. However, the repair pass is very expensive, ctx-size 256/chat max-new-tokens 16 were not completed, and FPGA interactive demo latency is not acceptable yet.

## Fixes Implemented

- Full GPT-2/BPE byte decode for generated token sequences.
- `--decode-ids`, `--prompt-raw`, `--prompt-chat`, `--temperature`, `--top-k`, `--top-p`, `--interactive`, `--dump-top-k`, `--dump-layer-stats`, and diagnostic `--probe-first-gemv`.
- GGUF ChatML prompt rendering with explicit `chat_template_applied` and prompt token ids.
- EOS/im_end stopping by default.
- FPGA saturated-output repair: exact `INT32_MAX/MIN` row outputs are recomputed on FPGA with that row duplicated across lanes, then substituted before accumulation. This keeps fallback 0 and keeps `lm_head` on FPGA.

## Key Findings

- Original failure was not tokenizer-only. Board and host decode matched; the replacement character came from actual generated byte `0xb6`.
- CPU-only chat baseline is readable. Example: `I'm doing great! How can I help you today?`
- Unrepaired FPGA diverged at the first real GEMV, layer 0 `q_proj_output`, with `8388608` outputs from `INT32_MAX / 2^ACT_SHIFT`.
- First GEMV probe showed fixed-point reference matched CPU closely, while mixed-row FPGA packets produced saturated row outputs.
- Duplicating a saturated row across all lanes recomputed correctly, so the repair pass is a valid FPGA recomputation workaround, not CPU fallback.

## Repaired Results

- Raw FPGA `Hello, how are you?`, max-new-tokens 16:
  `I hope you're doing well.\n\nI'm looking forward to seeing you`
- Chat FPGA `Hello, how are you?`, max-new-tokens 4:
  `I'm sorry for`
- Board CPU interactive smoke:
  `--interactive --backend cpu --prompt-raw unused --ctx-size 128 --max-new-tokens 1` generated token `28`, text `,`, `total_gemv_calls=211`, `cpu_gemv_fallbacks=0`, and `/stats` plus `/quit` worked.
- Repaired raw `Hi` first-token top-k:
  CPU top1 token `28` appears in FPGA top5; top5 overlap `2`, top10 overlap `3`, argmax still differs.
- Repaired raw max-new-tokens 16:
  `total_gemv_calls=4426`, `fpga_gemv_calls=4426`, `cpu_gemv_fallbacks=0`, `fpga_repair_jobs=169970`, no kernel oops/panic observed.

## Open Issues

- Repaired FPGA hidden/logits still differ from CPU; first large post-repair layer-stat drift is layer 0 `gate_proj_output`, then quantization error accumulates.
- Repair overhead is too high for S07: raw 16-token run took about `198.7 s`; chat 4-token run took about `321.3 s`.
- ctx-size 256 and chat max-new-tokens 16 were not run.
- Role-level GEMV breakdown is implemented for q/k/v/o/gate/up/down/lm_head. Exact low-level driver timing buckets for packet copy, input BRAM write, DMA setup, wait, and S2MM read are not instrumented yet.
- FPGA interactive mode is implemented but not yet validated as demo-usable because repaired FPGA latency is still too high.
