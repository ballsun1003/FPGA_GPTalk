## Packet Contract Under Test

The software checker compares packet bytes generated by the normal mixed-row path against duplicate-row packets for the same row and lane.

Expected packet contract:

- Row id in normal mixed-row packet: `row_group_base + lane`.
- Scale header order per block: lane 0 through lane 15, little-endian `int32_t` scale values.
- Scale beat grouping expected by hardware: beat0 lanes 0..3, beat1 lanes 4..7, beat2 lanes 8..11, beat3 lanes 12..15.
- Weight byte order per column: byte0 lane0, byte1 lane1, ..., byte15 lane15.
- DMA BTT unit: bytes.
- TKEEP: full beat, `0xffff`.

## S06.5.1 Classification

Root cause isolated:

- Not software packet byte layout.
- Not row id mapping in the packet generator.
- Not scale/weight byte extraction by the host runtime.
- Not input BRAM addressing or raw MAC, because mode1 block_acc matches CPU for the same affected rows.
- Not a single-column scale/output error, because one-hot mode0 passes at representative block boundaries.
- Current best classification: `MODE0_MULTI_BLOCK_ROW_ACC_OUTPUT_FAIL`.

This is an RTL-side Candidate 10 behavior after raw block accumulation. The likely failing region is mode0 scaled block accumulation into per-lane row accumulators, row accumulator lifetime/reset/update, saturation decision, or output emission after multiple active blocks.

Software repair remains diagnostic only. Since the isolated failure is post-block-accumulation hardware behavior, fixing it requires a separate RTL investigation stage, for example S06.5.2, with wrapper TB coverage before any Vivado build. No Vivado build or hardware artifact replacement was done in S06.5.1.
