## Active Board Result Before RTL Fix

- Board log: `logs/s05_6_1_multiblock_board.txt`
- Board CSV: `reports/s05_6_1_multiblock_board.csv`
- Result: FAIL 3 cases on active S05.5 bitstream.

Failures:

- `B_64x16_P4`: `INPUT_ADDR_PROGRESSION_FAIL`, first mismatch lane `4`, got `10`, expected `8`.
- `B_64x16_P5`: `WEIGHT_BLOCK_PROGRESSION_FAIL`, first mismatch lane `6`, got `55`, expected `21`.
- `E_576x16_P3`: `SATURATION_FAIL`, lanes `1`, `8`, `15` got `2147483647`, expected `-747`.

The `E_576x16_P3` debug registers showed low 32-bit `row_acc1=-747` while output/debug_out1 was saturated to `INT32_MAX`. This points at signedness/high-bit handling around variable-index row accumulation or final output saturation.

## RTL Fix

Modified `vivado_ip/rtl/gemv_q8_0_stream_core.v`:

- Explicit `$signed(...)` reads for variable-index `block_acc`, `scale_q`, and `row_acc`.
- Explicit signed helper wire for `row_acc_after_scalar_64` before saturation compare.
- Explicit `$signed(...)` in variable-index block accumulator update.
- Final mode=0 emit now saturates the final `row_acc[emit_lane]` directly instead of trusting a separately stored `row_out`.

Unchanged:

- 128-bit AXIS packet contract.
- TLAST/TKEEP validation.
- 16-lane geometry.
- `valid_lanes_reg` output emit fix.
- AXI DMA/input BRAM data path.
